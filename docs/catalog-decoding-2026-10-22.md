# 大目录读取与控制器交互

候选已实现目录读取并发限制、严格字节预算、大响应的 UTF-8/JSON 解析隔离，以及失败时保留已保存列表。它不改变远端服务，不安装远端插件，也不把写操作放入可重试队列。尚未发布或替换日常安装。

## 实现范围

- 仅控制器的 `session/list`、`workspace/follow` 和只读 `session/follow` 进入目录读取队列。全局最多两次、同一 Host 最多一次，最多十个未完成观察；排队超过十秒取消尚未派发的观察。已派发读取保留原协议期限，不重放消息、命令、传输或取消请求。
- 单份响应最多 8 MiB，按实际解压后字节计数，不相信 Content-Length。超过 1 MiB 的数据进入同一个复用 Worker；小目录在本机快速解码。Worker 的活动/排队输入合计最多 16 MiB、最多两个排队任务，总等待预算五秒。
- Worker 的 V8 old/young generation 上限分别为 128/16 MiB，栈 4 MiB；这些不是进程 RSS 上限，缓冲区、结果克隆和主进程另有成本。输入缓冲区入队时快照，不接受期间的外部修改。
- 正常任务按随机 id 核对结果后复用线程；取消或超时则退役该线程，确认 exit 前保留预留量。空闲三十秒退役，空闲线程不阻止进程退出。旧线程的消息不能完成新任务。
- WebSocket 基线按接收顺序解码，不能让紧随大基线的 end 帧抢先结束观察。积压最多 16 MiB / 256 帧；暂停后完成读取会恢复关闭握手，内部观察者一秒未关闭则只终止其自身。其他健康终端继续持有原承载。
- 编码、预算、繁忙和超时使用固定本机诊断；已保存目录保持可读。任意远端错误文本仍以通用提示处理，避免把正文或私人端点放进侧栏警告。原生远端客户端自身的启动/实时请求仍走其原接口，不将本项说成全部 UI 流量已增量化。

使用 Node 的本地 Worker 和资源限制，[接口依据](https://nodejs.org/api/worker_threads.html)。线程只接收待解析数据，不执行 RPC、不访问文件或模型服务；没有新增原生依赖。

## 测量决定

参考 Mac / Apple M4 Max、Node 24.16.0；每个方法与数据量各独立进程，固定生成数据，输入 SHA-256 完全一致。每组 100 次，计时前 GC，复用输入缓冲区，先做一次完整内容核对。以下为暖数据解码，复用 Worker 已预热；不包含应用或线程冷启动，不是原生切换时延。定时器每毫秒观察一次，它不是 CPU profiler。

| 生成会话数 / UTF-8 字节 | 总解码 p95，旧 → 候选 | 最大定时器间隔 p95，旧 → 候选 |
| --- | ---: | ---: |
| 100 / 47,552 B | 0.165 → 0.172 ms | 1.491 → 1.491 ms |
| 1,000 / 486,752 B | 1.538 → 1.544 ms | 2.860 → 2.808 ms |
| 10,000 / 4,986,752 B | 6.105 → 16.979 ms | 7.390 → 5.578 ms |

大目录在这些条件下的总耗时上升，主事件循环的定时器停顿缩短；约 5 MB 组的进程 RSS 峰值从 262.6 增至 365.8 MiB。结果克隆仍需主线程，不能宣称消除了所有停顿或整体连接更快。中小目录保持本机路径，以避免线程往返成本。最终原生交互目标仍须实测。

第一轮“一次一建 Worker”没有采用：约 5 MB 组 p95 为 27.798 ms，RSS 峰值 693.1 MiB；改为复用后再测 256 KiB 阈值，最后根据中等目录代价选择 1 MiB。三轮十八份原始 JSON 均保留在[测量目录](benchmarks/2026-10-22/catalog-json/)，附源码散列和 [SHA256SUMS](benchmarks/2026-10-22/catalog-json/SHA256SUMS)，没有删去不利结果。

## 实际验证

本机 `release:local` 通过 **88 文件 / 797 项**、typecheck、build、产物检查及可移植归档。归档 SHA-256 为 `0c20ac37001c888a8559c37499cca30227aef22b2ea061dffa56cddaa7682fc6`，仍为不可发布的 `.39` 测试候选。

将同一归档安装到独立 DSH 0.2.1-rc.2，使用真实 SSH 和生成 Home，通过公开 Session/Title API 生成 800 条额外元数据。SDK 实际返回 801 行、1,153,414 字节，超过大响应阈值；编译后的网关成功返回最新所选项目目录，原远端 PID 保持，模型请求为零。[安装包结果](benchmarks/2026-10-22/catalog-json/runtime-macos.json)与[603 条事件的旧版回退结果](benchmarks/2026-10-22/catalog-json/downgrade-macos.json)单独保留。这里没有替代原生桌面验收。

专项还覆盖：一百个项目共享两份 Host 读取且会话不串项目；真实 Worker 复用、输入快照、编码错误、排队取消和 idle 退役；大基线后紧跟 end 帧；取消不排在目录后面；静默关闭观察者时原承载中的另一终端仍可收发；预算失败保留旧列表且不泄露任意远端错误。

首次全量为 789/790，通过严格主机密钥检查发现了测试夹具就绪验证的缺口：有限随机端口且只检查 TCP 连接成功。已改为 OS 分配端口，并在加入测试信任文件前核对夹具自己生成的密钥及认证；占用端口和并发服务器回归通过。那次实际对端的完整身份未保留，不能将推测写成已证实归属；失败日志仍在私有诊断。生产 known_hosts 核验规则没有修改。

Gemini 实际审阅了流顺序、取消及资源管理：请求 `gemini-3.8-flash-high`，返回 `gemini-3.8-flash-n`，响应 `3p7aaq79H_rhytMP4d31uAc`；采纳有界关闭及保留具体本机错误。`retainStream` 原本已有幂等释放、ws 原本已有三十秒关闭期限，没有按相反推测改动。复用池的第一次复核超时；缩小为取消/id/idle 竞态后得到实际回复 `xKPaavnhGdWqytMPus_jsA8`，未指出具体竞态。实际测试与上述性能取舍仍独立判断。
