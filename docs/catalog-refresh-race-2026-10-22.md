# 正常目录变化不再直接中断历史同步

这是开发候选修复，尚未发行或替换日常安装。

[CI 39880097248](https://github.com/Biogod2020/dsh-ssh/actions/runs/39880097248) 暴露了目录订阅引入的一处回归：读取会话元数据时，项目流正好收到新变化。版本校验正确拒绝了旧响应，但直接把 `Remote catalog changed during this read` 写成了历史同步失败，导致增量历史验收在第一轮保存时报错。

修复保留原版本校验。遇到这种明确的本机版本冲突时，最多重新读取一次目录与会话元数据，再在同一个同步回调中完成最终校验和列表保存，或取得历史源。多个项目仍共用同一主机的读取；已经有更新的合并查询时直接复用。传输错误、主机所有权变化、禁用、存储错误都不触发这种重查，创建、取消、命令和传输不进入这条路径。

连续两轮都被新变化取代时，保留已有本机副本，等待后续同步；没有无界重试、额外 SSH 连接或已派发命令的重放。校验与消费之间不插入异步等待，旧结果不能趁重查逻辑重新覆盖新列表。

本机完整验证为 90 文件 / 816 项，以及 typecheck、build、产物校验。新增的两个回归用例在修复前失败，修复后通过；另有持续变化上限、Host 归属变化、禁用后停止重查、旧标题/成员不回退和丢失创建回执不重放检查。Gemini 实际审查了这次并发路径，未提出具体缺陷；模型反馈没有代替独立测试。

同一安装归档 `4386cad3901b6fef75f27db59c6502dd6ce073409df1e8c5815df73b9910efe2` 已通过三版本实际 DSH / loopback SSH 目录订阅与大目录读取，并再次由已发布旧 `.39` 读取回退导出的 603 个事件。安装包中 96 份源文件逐字节一致。这里只报告已验证的正确性，不把重查次数当成公网速度。

冻结的持续观测器与验收脚本未修改，没有放宽计时、失败或清理门槛。同一包的完整 0、3、30、300 秒控制器离线恢复已通过：离线读取本机历史、草稿保存/清空、换网关端口后恢复及远端原 PID 保留均通过；30 秒校准取得 11 个样本、两次新增且无失败。这仍不是 24 小时结果。对应新 CI 继续核验，不能将失败的旧 CI 算成已通过。原生界面、最终候选长期稳定性与发行/本机更新仍在总目标中。
