# 视图回收前的操作保护核心

核心提供“冻结新派发 → 等待已派发操作 → 保存已结束的未知结果元数据 → 核对同一拥有者再释放”的状态机。现在已把单次 RPC 的观察接入远端页面启动：沿用 SDK 的请求和完整回执，不更换 Connection 服务或全局网络函数。**逻辑流、等待用户回答的请求、网关冻结和自动回收尚未接入**；完整待处理数量保持未知，不改变当前视图释放行为。整体里程碑仍未发布。

## 已实现与验证

- 未确认传输覆盖时返回未知，不把没有观察到操作当作零个操作。预留与实际派发分开；派发前取消不会被记成远端结果未知。
- 冻结后同步拒绝新派发。尚未派发且被拒的预留立即结束，解冻后不能再使用旧句柄；重复标记已派发操作会使覆盖度失效，保留原等待。核心没有命令、参数或重放回调。
- 等待回执的操作不能冒充已结束。只有已结束且未确认的观察能写本机元数据：本地随机观察 ID、开始/结束时间、固定类别、http/stream 和可选所选会话 ID。不保存端点、原始 RPC ID、正文或命令。
- 释放凭据绑定冻结拥有者与传输组合。保存期间重新核实传输，即使经历 false → true，也会使旧冻结失效，必须取消后重新检查。缺失或非字符串凭据不能匹配初始空状态。
- 持久化每批最多 64 条；逐项核对保存或已清除回执后才移除对应内存记录。保存失败保留保护。取消释放可以恢复派发，迟到保存不能让旧释放凭据复活。4096 条观察上限使覆盖度变为未知，不阻止正常操作，也不自动丢弃受保护视图。

17 项专项检查包含真实私有 Store 写入及重开，验证本机未知结果记录存续且不串 Host。Gemini 实际审阅 `OhbbauzPB4Ll5NoP7aeX6AY`，请求 gemini-3.8-flash-high、服务返回 gemini-3.8-flash-n。空凭据、被拒预留和覆盖度失效的三条新回归先实际失败，修正后通过。未照搬“任何派发拒绝都移除 active”的建议，因为它会误删已经派发的等待；实现只结束尚未派发的预留。

## 核对 SDK 的完成时点

新脚本加载未经修改的实际 `0.2.1-rc.2` 浏览器 SDK 工厂，使用模拟的 public Context 和 HTTP 响应，直接调用其公开 `installConnection` 与 RPC：

1. 本地目标校验失败，没有进入传输，不生成未知远端结果。
2. HTTP 响应头已返回但 JSON 还没读完，观察仍待完成。
3. RPC 身份不匹配，或派发后 signal 中断，保留未知结果；不重发。
4. 远端业务拒绝的有效回执是已确认失败，不等同于成功，也不是自动重试依据。
5. multipart 元数据已读取、二进制附件仍在解码，观察仍待完成；以 SDK 的完整 RPC Promise 为边界。
6. 两条未知结果经实际 Store 保存后才能取得释放凭据，重开 Store 仍可读。

这个检查使用实际 SDK 代码，但不是完整页面、真实网络或原生 UI。不能用响应头、单次 fetch 完成或半份二进制解码替代 Client 的完整回执。[原始结果、源码散列与复现命令](benchmarks/2026-10-23/operation-ledger/README.md)。

## 剩余接入

页面启动已提供 scoped fetch，普通 Client 贡献装饰当前公开 RPC 实例的 call 方法；待 SDK 完成 JSON/二进制解码及回执校验后才结束对应观察。下一步要补逻辑流和等待用户回答的远端事件，再与网关派发冻结、全部会话的终端/草稿状态组合，持有冻结直到准确视图移除。实际 SDK 的插件启动是并发的；仅调整 manifest 中的顺序或 inject 列表，还不能证明覆盖启动期请求。长期只读 follow 订阅也不能一律当作未完成写操作。

内存预算、自动回收、原生 100 次暖切换/30 次冷打开与焦点/休眠矩阵、最终候选 24 小时持续验收仍未完成。没有把本核心、绿色单测或 mock 契约检查当作这些项目的交付。

## 页面接入的实测范围

新增 11 项 Client 检查，包括真实 Cordis 4.0.5：Host 入口被移除时页面观察仍保留，根 Context 结束时恢复 RPC 方法，替换根时不会被旧清理反向覆盖。默认 SDK 在首次 await 前派发 fetch；实际未经修改的 SDK 并发 A/B 与延迟二进制检查均通过。自定义调用先 await 再派发时不能沿同步调用栈关联，明确使局部关联失效，保持部分覆盖；不使用浏览器不具备的 AsyncLocalStorage，也不改 SDK 工厂。

启动阶段还没有 RPC 装饰器的请求，其 JSON 便利读取方法和 clone 消费会结束一份未知观察，保留原 Response receiver、返回值和拒绝；未绑定的 multipart 或直接 ReadableStream 消费不会被冒充完整 SDK 回执，不靠响应头或超时强行清零。自定义 fetch/rpc/worker 流保留原组合。诊断没有正文、参数或私有端点，完整 pendingRequests/unconfirmedOperations 始终为 null，没有开放自动释放入口。

新的 Gemini 实际审阅 `JyLbarbpDZik5NoP1OqCwAQ`，请求 high、服务返回 flash-n。采纳读取方式和根拥有者生命周期问题；未采纳“普通并发必然交叉覆盖 current”的判断：current 是 finally 恢复的同步调用栈槽位，微任务不能插入另一段同步函数；实际默认 SDK 并发检查验证 2 → 1 → 0。额外 async 包装的缺口保留为未知，不冒充全面覆盖。

相同 2c5a734 候选完成 99 文件 / 916 项和三个实际运行时的安装/SSH/序列化检查，旧 `.39` 回退通过。真实网页 Client 可启动、渲染生成历史并创建/选择分支；这不能替代真实页面内部计数或原生冻结验收。[源码散列、完整原始结果与真实截图](benchmarks/2026-10-23/unary-observation/README.md)。
