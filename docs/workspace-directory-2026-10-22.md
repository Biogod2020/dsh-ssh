# 同一主机共用项目增量订阅

这是开发分支的候选实现，尚未发布 npm 或更新日常安装。归档仍沿用测试版本号 `.39`，以 SHA-256 区分，不能重新发布已占用的版本。

## 用户会得到什么

连接过的主机只建立一条项目目录订阅，多个项目与后续列表刷新共用。远端添加、删除项目、调整会话归属或归档会话时，本机接收变化；不再每两秒重新下载同一份项目基线。打开离线侧栏仍先读本机数据，不会因此建立 SSH。

旧请求晚到时不能把新列表覆盖回去。例如，读取旧列表后在远端归档会话，归档事件先更新了本机，再收到旧响应，此时旧响应会被拒绝。保留的本机历史正文由用户单独管理，归档远端会话不会自动删除本机副本。

会话标题、运行状态仍使用每主机合并的 `session/list` 查询，最多复用两秒；官方项目流没有这些完整增量。本轮没有声称所有目录流量都已改成补差。

## 协议与失败处理

对照实际安装的 DSH Workspace Controller，复用 `workspace/follow` 的 `baseline`、`replace`、`upsert`、`remove`、`order`、`archived`、`pinned` 帧。投影只保留项目身份、会话归属和归档集合；当前会话列表仍按更新时间排序，项目排序与置顶帧不会触发无关的会话元数据读取。

- 每代订阅必须从基线开始。收到删除后，同一代的迟到更新或替换帧不能恢复该项目。
- 项目目录、会话列表组合读取携带本机版本。变更前后、增量到达、失联或切换通道均使旧版本失效；这只是本机并发隔离，不是远端持久游标或数据集身份。
- 基线完成即释放只读调度槽，长订阅不会占住每主机的读取名额，也不阻塞取消等写请求。
- 只有当前已有的 SSH 通道可供使用。换通道时关闭控制器自己的只读订阅，仍正常的用户终端继续留在原通道；不迁移或补发用户输入。
- 长订阅每 30 秒发送 WebSocket ping，10 秒未收到 pong 就结束该只读观察。HTTP 健康响应不能替代这项检查。下次只读查询可重建观察；命令、传输与聊天请求不会重放。
- 消息与解码积压沿用有界读取；保留的目录另外限制为 8 MiB、20,000 个项目、100,000 条会话归属引用，删除标记也有上限。未知帧、无效类型或超限会结束该观察，保留磁盘列表，等待重新校验。

官方流没有跨断线的持久游标。新通道需要重新接收完整项目基线；历史正文仍走已有的本机事件游标补差，不能将两者混称为同一协议。
