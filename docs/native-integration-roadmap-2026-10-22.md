# DSH SSH：原生融合、连接体验与长期历史的迭代方案

日期：2026-10-22（America/Los_Angeles）。基线：已发布的 `@biogod/dsh-ssh@0.3.24-jay.39` 与 DSH Desktop `0.2.1-rc.2`。

官方参考快照：`deepseek-ai/deepseek-harness` master `687f282e8625c6b8d11ff58211a90524be2e4317`，在编制本方案时重新核对。

本文是后续实施方案。现有能力、待做工作、建议目标分别说明；这里的性能数字是验收目标，不是已经测得的成绩。各轮独立交付，版本号在实际发布时分配。

## 1. 最终要得到的体验

打开应用就能看到本地与远端项目、上次的会话和已经保存的历史。点击会话立即响应，先显示本机内容，联网校验在后台完成。聊天、文件、终端和模型设置始终属于同一台明确的主机。短暂网络抖动尽量自动恢复；用户不必为了刷新一个列表重新连接整台机器。

远端历史长期保存在本机磁盘，退出应用和重启后仍可读。同步同时减少网络、磁盘和界面工作：只传缺少的事件、只写新增的数据、只渲染当前可见部分。用户可以按主机、项目、会话清理，并收到空间提醒；系统不按时间自动删历史。

完整远端 DSH 与本机客户端拥有不同生命周期。关闭视图、断开连接、退出本机应用，都不等于停止远端任务；停止任务是单独操作。模型依赖本机网络时，界面会明确说明本机离线后的实际能力。

## 3. 架构分工

| 层次 | 负责什么 | 不承担什么 |
| --- | --- | --- |
| 官方原生界面 | 统一侧栏、会话操作、搜索、面板、快捷键、当前主机显示 | 不猜测远端路径是否为本机目录 |
| 每台主机的客户端数据与权限上下文 | 工作区/会话数据模型、命令路由、连接代次、能力协商 | 不通过切换一个全局变量，把既有异步操作改发给另一台机器 |
| 本机持久副本 | 历史、目录元数据、草稿、索引、离线读取和清理 | 不成为远端运行状态的权威，不把历史作为待执行队列 |
| SSH 插件 | 主机配置、信任检查、连接、远端准备、认证网关和服务发现 | 不复制模型认证、不自动接受陌生主机密钥 |
| 远端 DSH | Agent、模型请求、远端插件、文件/终端、权威会话日志 | 不因本机关闭界面就退出 |

官方现有 Host → Remote → Client model → UI 的分层可作为整合基础。[客户端架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/web-client.md)

### 主机和会话身份

- 客户端引用至少携带 `hostId + workspaceId/sessionId`。别名、显示名称、IP、路径都不能单独充当会话归属证明。
- 主机登记记录、登录账号/profile、服务实例身份和已验证信任关系分开记录。别名变化不迁移历史；指纹变化必须先重新核验，不自动把旧副本归给新机器。
- 文件、终端、模型设置和菜单动作在创建时绑定所属主机。切换选中会话不会改变已经派发操作的归属；迟到响应只更新它原来的目标。
- 远端路径由远端解释和规范化，保留对应平台的路径规则；不向本机文件 API 传入拼装的 `ssh://` 字符串。
- 前端主机引用是本地路由信息；远端 API 仍使用它自身的真实 ID，避免把客户端合成 ID 写入正式远端会话。

### 能力协商

首次可信连接获取 DSH 版本、协议版本、非敏感的服务/历史身份及受支持能力，例如原生导航、只读增量、目录流和取消回执。实际能力优先于单看版本号。协商失败保留本机历史和旧兼容路径；不自动安装插件、改模型配置或重启已有远端服务。

## 4. 迭代顺序、交付物和退出条件

| 轮次 | 用户收益 | 主要交付 | 依赖与退出条件 |
| --- | --- | --- | --- |
| 第 0 轮：建立基线 | 能定位慢在连接、读取还是渲染 | 本机测量、真实 SSH 网络夹具、可重复对比报告 | 不依赖官方；先冻结数据、网络条件和指标口径 |
| 第 1 轮：导航和恢复 | 点击立即响应，短暂抖动少打断 | 缓存优先切换、统一状态、去重探测、安全读取恢复、菜单能力表 | 主机归属回归通过；不再为普通切换执行整套准备流程 |
| 第 2 轮：磁盘和显示 | 历史越长也不反复整份写、整份解析 | 分段历史、分页读取、视口渲染、草稿恢复、旧格式迁移 | 新增小批事件不重写旧段；崩溃/清理/回退验收通过 |
| 第 3 轮：同步和带宽 | 不反复抓列表，补差不抢交互 | 事件订阅、按主机聚合、只读恢复、原生增量可选接口 | 新旧远端都可用；断线补差、旧回包和代次切换正确 |
| 第 4 轮：原生接口 | 菜单、快捷键、模型设置像本地一样一致 | 主机数据源、命令路由、稳定远端视图的正式接口和适配包 | 有官方接口时切入；没有时独立插件照常迭代 |
| 第 5 轮：任务生命周期 | 知道远端是否还在运行，停止结果清楚 | 独立状态、持久操作回执设计、准备结果核查、服务停止入口 | 不重放，结果未知可核查；不承诺进程崩溃/机器重启后自动恢复 Agent |
| 第 6 轮：网络模式与扩展 | 远端无模型网络时有明确选项 | 本机 Agent/远端执行、可选模型中继、离线附件与搜索增强 | 核心体验完成后单独实现与验证，不阻塞前五轮 |

第 1、2、3 轮是近期重点。第 4 轮的接口设计可提前并行推进，但正式上游接入取决于维护者；不让官方等待时间阻塞已发布插件的改善。第 5 轮已有的生命周期信息和取消反馈可提前小步交付。

## 5. 第 0 轮：先把“慢”测清楚

记录从点击到选中、读取本机首屏、SSH 握手、认证、服务探测、客户端就绪、补差完成、可输入的分段时间，同时统计请求数、收发字节、历史读写字节、主线程长任务、内存和文件句柄。诊断默认留在本机，不采集聊天正文、命令输出、凭据或私人端点；用户主动导出时先预览。

基线与候选都用同一台参考 Mac、相同 DSH/构建、相同数据和负载。记录实际硬件，不在系统空闲程度不同的结果间挑优势。区分应用冷启动、首次远端客户端加载、已加载客户端切换和磁盘副本首屏，不将它们混成一个“连接速度”。

测试集建议：100 / 10,000 / 100,000 条事件；混合中英文、长工具输出与附件引用；10 / 100 个项目；已连接 1 / 3 台主机。1 MiB 小会话和约 100 MiB 大会话分别测量。大事件另测，不能用大量短文本替代。

网络条件：loopback；RTT 80 ms、20 Mbit/s；RTT 200 ms、2 Mbit/s、1% 丢包；完全离线；断开 3/30/300 秒；睡眠恢复；模型慢但 SSH 正常。优先使用本机测试代理注入，不修改用户系统路由。

每组暖切换至少 100 次，冷路径至少 30 次，报告 p50/p95、最大值和失败次数。模型 fixture 只验证消息链路，不用于宣称真实模型效果或速度。

### 首批验收目标

以下目标在第 0 轮完成后冻结；若基线揭示条件不合理，应在实施前说明调整依据，不能在测试失败后悄悄放宽。

| 指标 | 初始目标 | 测试条件与范围 |
| --- | --- | --- |
| 点击反馈 | p95 ≤ 100 ms | 已显示的侧栏，正常主线程负载，不等待 SSH |
| 本机历史首屏 | p95 ≤ 300 ms | 已有完整磁盘副本，应用已启动，按窗口读取；大历史不整份解析 |
| 同主机暖切换 | p95 ≤ 250 ms | 客户端已就绪、会话已有本机内容；不包含冷启动和模型回复 |
| 已有服务恢复可交互 | p95 ≤ 5 s | 前台应用收到 online 事件或用户触发重连起计，RTT ≤ 80 ms/20 Mbit/s、信任有效、无需人工认证和安装 |
| 无变化同步 | 0 条历史正文、0 次旧历史段重写 | 允许小型游标/清单、索引检查和协议开销，不宣称全连接零流量 |
| v2 单独写入时的新增成本 | 只新增对应段与小型元数据，旧段重写为 0 | 最终存储优化门槛；搜索索引单独记账 |
| v1/v2 兼容双写时的新增成本 | v2 路径仍只新增；v1 路径允许兼容性整份写入 | 过渡发行单列 v1、v2 和总写入量，额外开销预算实施前冻结；不得宣称整体已达到 v2 目标 |
| 安全边界 | 错主机写入、自动重放、无提示丢历史均为 0 | 任一出现即阻断发布，不能用平均值抵消 |

首次安装下载、人工验证码和真正断线中的写操作没有固定五秒成功保证；它们需要进度、取消观察和准确回执。

## 6. 第 1 轮：切换和恢复先不等网络

### 切换路径

1. 用户点击后立即更新选中态和主机标识。
2. 优先展示该会话已加载视图；否则读本机首屏和草稿。没有副本时显示具体阶段，不用覆盖整个应用的加载页。
3. 后台单独恢复连接、校验归属并同步。导航有自己的代次；用户切到另一会话后，旧请求不能把界面拉回去。
4. 同一主机复用已加载客户端和连接；普通切换不做安装器探测、不重新创建工作区、不强制刷新所有列表。

设置与菜单显示明确的“本机 / SSH: 主机”上下文。补齐“远端模型设置”直接入口，减少用户依赖键盘焦点和隐蔽快捷键。

### 状态与错误

分别展示连接状态、远端服务状态、任务最后确认状态、本机副本/同步进度。离线时可写“历史已保存，正在重连”“任务最后确认运行于某时”；不能把旧缓存的 running 当成当前事实。准备结果不确定时提供“核查远端准备结果”，不把重新安装当成默认恢复。

将错误对应到具体动作：认证需要补凭据；密钥变化需要核验；网络抖动后台恢复；远端服务退出检查原进程/日志；模型错误只影响任务，不据此拆掉正常 SSH。重复同类故障聚合成一条可展开提示，保留原始错误以便诊断。

### 恢复策略

- 对同一主机连接建立和同一只读同步做合并，后台恢复加退避与抖动，用户明确点击重连可立即再检查。
- 自动恢复仅重新建立传输、订阅和白名单内的非激活只读查询。安全性按 RPC 的语义判断，不按 GET/POST 判断。
- 已派发的消息、命令、传输、取消、安装和修改配置请求不自动重发。丢失回执时保留结果未知，恢复后读取真实状态。
- 某次健康检查超时不能关闭仍有正常流量的终端；明确失效的承载才更换。并发旧承载有边界，但不能为了腾配额主动杀健康终端。
- 交互认证、未知/变化的主机密钥、权限拒绝不进行无休止自动重试。成功恢复后合并提醒，不在每次后台检查弹通知。

### 内存与草稿

内存保活与磁盘保留独立。先记录每个远端客户端的内存，再按预算保留最近使用视图。释放非活动视图前先保存文字草稿和导航；有活动终端、未保存内容或正在等待回执的操作时不能静默淘汰。观察已结束的“结果未知”可保存关联标识、主机身份和状态后释放视图，不因它永远未知就永久占用客户端内存。保存失败时保留视图并提示，不能丢草稿；达到预算且无法释放时提示占用，不结束远端任务。

文字草稿按主机会话私有保存，重启后恢复；采用独立轻量文件/存储接口，不依赖历史 Store v2 完工。附件选择句柄不假装持久化，失效时提示重新选择。本机历史清除、草稿清除、远端删除分成不同动作。

验收：本地与两台远端各两条会话往返切换；草稿、滚动位置、文件/终端归属、输入焦点和快捷键正确；网络抖动期间能继续阅读和切换，取消只派发一次。

## 7. 第 2 轮：把本机历史做成长期数据

### 存储选择

优先采用不可变的分段事件文件和小型清单/索引，避免为当前纯 JavaScript 安装路径引入未验证的原生数据库依赖。搜索索引是可重建的派生数据，不能替代原始事件。若后续需要 SQLite，先验证目标 Node、系统、打包和升级，再独立引入。

每个会话清单记录主机/会话身份、格式版本、历史代次、已持久化连续游标、完整性、段范围和校验值；清理状态与写入代次独立记录。每批新增只提交新段，再原子提交清单，最后更新总索引。网络接收成功不等于已保存，磁盘提交完成后才能推进持久游标。

第 2 轮即固定代次隔离：目录为 `history/<hash(hostId, workspaceId, sessionId)>/<localGenerationId>/`，每代独立清单，会话入口只指向当前活动代。清单保存可用的远端数据集/历史代次；旧协议没有这些字段时明确记录为未知，不把自生成的本地代次或服务进程 ID 当成远端证明。换代封存旧代，不覆盖旧清单，不与旧事件序号共用段路径。

清单同时记录已覆盖区间与“从开头连续保存到哪里”。可先保存经校验的最新窗口以供首屏阅读，但不能把尾页最高序号当成完整连续游标。后台只补区间缺口，交汇处按代次、序号和内容校验去重；只有缺口真正落盘补齐后才提高连续游标。

- 默认每批最多 500 条，并增加字节预算；大工具结果必须单独测试，不能只靠条数限制内存。
- 大事件采用可验证的流式写入或协议分块；旧协议超出能力时明确失败并保留原副本，不能静默截断或陷入零进度循环。
- 段与清单写入保留 `0700/0600` 权限、fsync 和原子替换纪律；验证平台需要的目录持久化语义。文件权限、锁和原子替换通过平台适配层处理；Windows 需另外验证 ACL、占用文件和断电恢复，不能用 POSIX 权限测试替代。崩溃可留下未引用临时段，恢复只回收已证明不属于有效提交的文件。
- 同一 DSH Home 只能有一个有效写入者；跨进程锁须识别实例，不能仅凭 PID 或超时抢占仍活跃的写入。锁冲突时其他客户端可只读。
- 索引可从有效清单重建；单个损坏会话不能阻断全部历史阅读。损坏数据保留，重建写入新副本。

### 读取与搜索

按最近窗口和滚动位置读取所需段，长列表/消息采用虚拟滚动；重渲染保留稳定事件 ID。只读历史与原生实时聊天切换要保持位置，避免补差后跳回底部。

换代时先创建待载入的新代；新代首屏窗口校验并提交前，保留上一代只读快照，明确显示“远端历史已变化，正在载入”，不把旧内容当作新代事实。新代首屏就绪后再切换显示和活动入口；远端确认为空时提交空基线并说明。视图键包含主机、日志代次和事件身份，不跨代仅按相同 seq 复用消息或滚动锚点。实时输入始终绑定已验证的新运行上下文。

先支持本机标题、主机、项目搜索，再异步建立正文索引。结果注明“本机已保存 / 已向远端校验”，离线搜索不自动连接所有主机。无副本的远端正文仅在用户明确搜索范围且有权限时查询。

### 清除与提醒

默认不自动过期。延续 512 MiB、100 条会话、保存满 30 天提醒和推迟 7 天的现有规则；这些是提醒阈值，不是删除期限。后续可配置阈值和仅在超额时提醒，不能把不提醒解释为允许自动删除。

清除支持主机/项目/会话选择，展示预计释放空间；不触碰远端会话或运行任务。按被清理的键建立持久写入屏障，取消其排队同步，阻止旧回包重建副本；其他会话不受影响。屏障采用持久递增的本地写入代次，不是布尔开关。清除时推进代次并关闭写入；用户明确再次打开或启用同步时再次推进代次并允许新任务写入。每个同步任务携带发起时代次，最终提交仍须与当前允许写入的代次完全一致，重启不能复用旧代次。因此重新打开也不能放行清理前的迟到回包。普通回退不自动恢复用户已清除的历史；旧备份由用户显式恢复管理。

清除范围包括应用管理的该会话 v1/v2 副本、迁移归档和派生索引引用。用户另存的导出文件或独立备份不扫描、不擅自删除，也不会被应用自动恢复。双写模式同时清除旧版可见文件；v2 模式不能把仍可被旧版扫描到的 v1 原件留在活动目录。

远端删除项目或会话也不自动删除本机历史。保留的副本标为“来源已删除/暂不可验证”，仍可搜索和阅读；原来的远端执行入口不能假装仍有效。

### 从 v1 迁移

按会话惰性迁移，空间不足时继续旧格式，不强迫全库转换。迁移准备只读旧文件，生成新段、比较事件序号/内容与首存时间；通过验证后才提交新格式。准备阶段中断仍以旧副本为准，不能留下两个可同时写入的活动入口。

启用仅 v2 写入时，将已验证的 v1 原件原子移入旧版不会扫描的应用管理归档目录，并记录切换进度；回收这些归档前先通过回退导出验收。对未完成搬移的崩溃切换按提交记录恢复，不能让旧扫描器误认它为当前副本。迁移或回退前确认旧版写入进程已退出；旧版不识别新锁，因此不支持新旧程序共享同一 Home 并发写入。

需要保持旧版读取兼容的试用阶段保留 v1 双写，明确它仍有整份写入成本，不能宣称达到新写入目标。过渡期独立测量两条写入路径及总量，超过预先冻结的兼容开销预算就停用试用，不能只展示 v2 的漂亮数字。切换为仅 v2 后，不承诺旧版程序读到最新历史；回退工具以当前活动清单和清除屏障为准，离线生成干净的兼容 v1 集合，核对新增事件和清理结果后才启动旧版。不能直接暴露或恢复包含已清理会话的旧目录。

更早版本会先读取最新尾页，因此确实可能留下“尾部已保存、前段缺失”的 v1 副本；这类副本按旧分页接口补齐前段，保留已有尾部。`.39` 新副本则从开头向后提交连续批次，中断后补后段。迁移要分别识别两者，不能统一假设缺口总在尾部，也不能把尾页序号当成完整保存进度。

v1 只能表达经过旧规则校验的连续范围，兼容双写期不启用仅 v2 能表达的多缺口持久化。仅 v2 模式可按覆盖区间保存；降级前如尚有多个不相连区间，保留所有 v2 原件，先补齐或生成可验证的兼容连续副本。无法无损完成时不强行替换数据，可保留新版本只读入口；不能为让旧版启动而丢掉已经保存的区间。

验收：10 万事件与大工具结果、随机落盘阶段杀进程、磁盘满、权限异常、索引落后、段损坏、清理/同步竞态、多进程竞争、迁移中断和回退。旧记录内容、事件顺序与 firstSavedAt 全部保留。

## 8. 第 3 轮：少传、少查、不过度抢占

### 三类数据分别同步

| 数据 | 策略 |
| --- | --- |
| 版本固定的静态资源 | 以主机信任身份、模块内容版本和权限上下文隔离缓存；保留压缩和 ETag/内容哈希。不缓存认证票据、私有 HTML 或设置响应 |
| 项目、会话目录 | 每主机一次订阅/聚合，多个项目复用；先显示本机目录，再接收变化。删除标记和订阅代次防止迟到数据复活旧行 |
| 会话历史 | 本机连续游标与远端稳定日志身份比较；只读缺少的范围，分批提交。不用列表的用户发言时间代替历史游标 |

官方 `workspace.follow()` 现有在线增量，重连仍发送基线，没有持久游标补传。先复用已有流减少轮询；跨断线只补目录差异需要额外协议，不能假定已存在。[Workspace Controller](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/api/workspace-controller/README.md)

### 建议的正式历史接口

下面是待协商的协议内容，不是已有 API：

- 只读 `head`：稳定数据集身份、持久历史代次、当前序号、协议能力。
- 只读 `delta`：输入数据集/代次、`afterSeq`、固定快照上界、事件数/字节预算；输出连续事件、已覆盖上界和继续位置。
- 可续接的变化订阅：只用来提示有新数据，客户端依旧以已提交游标补差；订阅断开不能导致丢记录。
- 数据集身份和历史代次持久化。普通服务重启不重建历史代次；重置、截断、重新导入或不兼容重写必须换代。
- 客户端只在事件连续且已落盘后提交新游标；同一序号不同内容报冲突。旧响应必须匹配主机、会话、日志代次、同步任务和清理代次。
- 发现换代/回退/断档时保留原副本，另建新代并展示原因，不把不相容历史拼接起来。旧版本没有可靠日志代次时，依据现有不可变事件约定和边界校验工作，不能声称能零成本发现任意人工重写。

生成中的实时 token 可以暂存用于显示，但永久副本以远端已提交的日志为准；最终事件到达时替换对应临时内容。未提交流不能冒充完整保存，断线后按正式日志和实时恢复协议核对，避免重影和重复内容。

能力支持时使用新接口；不支持时继续使用 `.39` 的只读辅助进程。不会为了省一次进程启动静默安装远端插件或重启用户正在运行的 DSH。

### 调度与连接

活动会话、用户搜索和交互操作优先于旧历史补齐。相同读取合并；对只读路径设置并发/字节预算和取消。先保留现有最多两批历史读取的全局限制，再根据测量区分主机预算；窗口隐藏或用户输入繁忙时降低后台补齐优先级。

事件订阅正常时避免同一数据的重复轮询；无相应能力时延续有界的运行中/静默校验。应用启动只读本机目录，不为了展示离线项目建立所有 SSH；已连接且用户启用同步的会话可由 Host 层调度，不再依赖侧栏恰好轮询。

多主机恢复时先连接当前活动主机并恢复交互，非活动目录基线排队；已经正常的流不因此关闭。限制同时处理的大型目录基线，合并与渲染按时间片让出主线程，体积大的完整 JSON 基线在 Worker 等可隔离解析路径处理，不假设一次 JSON.parse 可以被交互抢占。先显示本机目录，解析完成后再按所属代次应用变化；损坏或超预算基线保留旧视图并报告，不堵塞输入。恢复五秒目标只针对指定正常网络条件下的前台活动主机，不扩张成所有主机在任意弱网下同时恢复。

大传输和后台历史不能堵塞取消/状态等交互。先做逻辑队列与背压；如果实测同一 SSH TCP 的丢包阻塞仍明显，再为重传输启用有上限的独立承载。逻辑优先级不能消除 TCP 层阻塞，不能仅凭多 channel 就宣称已隔离全部网络影响。

已有正常终端不为重新连接而重建；真实断线后的普通 shell 不假装能继续附着原 PID。需要跨断线持久终端时，另用明确可附着的会话后端，作为独立能力。

本轮先优化插件自己控制的读取与调度。嵌入远端原生客户端内部的启动、尾页和实时状态请求仍须计入总成本；在没有正式接口前，不能据本机历史只补差异就宣称所有界面流量都已改成增量。

验收：后台同步大历史同时输入终端/取消任务；连续断网再恢复；同列表时间戳新增助手/工具事件；100 项目目录变化；相同序号的换代历史；新旧协议混用。分别记录协议正文、脚本、压缩和 SSH 总流量，避免只报最小那部分。

## 9. 第 4 轮：与官方原生融合

### 争取的最小接口

| 接口方向 | 官方负责 | 插件负责 | 没有接口时 |
| --- | --- | --- | --- |
| 主机数据源 | 允许多个有归属的数据模型进入原生列表 | 连接远端、提供模型和能力 | 保持现有合并适配，不把合成 ID 交给本机 Controller |
| 导航与命令 | 以所属主机路由打开、新建、重命名、归档、搜索和快捷键 | 返回远端支持的操作、权限与状态 | 按能力显示菜单；缺能力的动作明确说明，不误调用本机 |
| 原生远端视图 | 生命周期、尺寸、焦点、快捷键和主机上下文的稳定扩展点 | 建立可信远端客户端及释放观察 | 保留现有嵌入方案，并隔离适配代码 |
| 历史和目录补差 | 有权限控制、代次、字节界限的正式读取协议 | 本机存储、调度、兼容旧版 | 继续现有只读历史辅助进程和基线目录 |
| 服务与操作回执 | 可观测服务身份、任务事实、可选持久回执契约 | 建立/关闭传输、展示观测结果 | 保留真实未知状态，不自行补发原操作 |

原生界面包含权限、运行中归档、pin、fork 等语义。每个动作建立能力表并在对应主机执行；不只是给远端行加一套看似相同的按钮。原生搜索也应区分本机已保存结果和远端查询结果。

### 两步改造界面

第一步获得稳定的原生远端视图扩展点，替换布局类名探测、页面注入和焦点补丁，继续保留各主机客户端隔离。第二步在官方支持主机绑定和插件模块隔离后，逐步复用聊天、文件、终端组件；不能把多个远端的任意插件直接加载进同一个本机全局上下文。

先对齐 API Gateway 的认证、权限和版本语义，再考虑复用底层连接。官方使用 OpenSSH/helper，我们现有 ssh2 路径继续承担完整远端 DSH；不能因为都叫 SSH 就直接共享生命周期，或同时加载两套重复执行的工具。

当前官方暂不收外部 PR；已在 [#8385](https://github.com/deepseek-ai/deepseek-harness/discussions/8385#discussioncomment-19125361) 发布中英文实现说明。后续可提供最小接口草案、隔离示例和契约测试，先争取推荐社区插件，再评估内置。保留 Apache-2.0 来源及 NOTICE，代码采用前与维护者确认包装和许可证安排。官方未接受之前，文档继续明确社区插件身份。

验收：新官方接口开/关与旧版回退均通过；本机、远端 A、远端 B 同 ID 的操作绝不串主机；远端权限拒绝不能回退成本机执行；禁用插件清理本机视图和订阅，不触碰远端任务。

## 10. 第 5 轮：远端任务和停止回执

把任务、服务、传输的状态分开：可以“连接已断，但服务最后确认在线”；也可以“SSH 正常，但某个任务的模型调用失败”。重新连接先核对服务和会话身份，再读取任务事实。

操作分为未派发、已派发待回执、已确认、结果未知。请求 ID 用于关联，不自动等于远端幂等保证。协议支持持久回执后才可按 ID 观察；没有回执时直接读任务真实状态或提示核查，不能用重发推测上次是否执行。

取消按钮立即反馈“正在请求停止”；确认后显示实际结果。断线时只能显示“停止结果待确认”，恢复后核查。关闭取消请求的观察不代表远端任务已停，停止 shell 也不等于其所有子进程均已结束。

服务实例变化时结束对旧连接的无限等待，改为可操作的“原实例不可达，原请求结果未知”，保留原请求和服务身份，并允许用户检查新实例或明确发起新的操作。观察可以结束，原任务结局仍可能未知；不能因出现新 PID/实例就宣布旧进程、脱离的子进程或集群作业已结束。只有可靠回执或匹配原身份的实际进程/任务证据才能确认相应事实；证明原 Agent 已退出也不等于证明取消请求成功或全部外部任务已停止。

关闭视图、断开主机、退出本机、停止远端服务分别提供语义和必要确认。停止服务前列出已知活动任务；服务身份变化不自动重跑安装或启动第二份服务。准备回执不确定时只读核查原结果，再决定是否需要新的用户操作。

远端守护运行优先复用已有服务/调度系统；普通 detached 进程无法保证跨主机重启、管理员杀进程或 logout 清理策略存活。安装用户服务、修改 lingering 或接入集群调度是后续独立交付，不在恢复连接时附带修改机器策略。

验收：退出/重启本机后原远端任务和服务身份保留；主动停止只派发一次；ACK 丢失、服务崩溃、PID 重用、并存新实例、残留子进程、任务已结束与准备结果未知分别给出准确状态，不出现无限加载或虚构完成。

## 11. 第 6 轮：网络模式和可选增强

| 模式 | 适用情况 | 本机离线后 |
| --- | --- | --- |
| 完整远端 Agent，远端可访问模型 | 长任务优先模式，现有实现 | 远端进程和模型网络可用时继续 |
| 本机 Agent、官方远端执行 provider | 远端没有模型网络，本机有 | 本机后续推理停止；已派发进程的存活取决于执行后端，官方 helper 当前存在租约清理 |
| 远端 Agent、经本机中继模型请求 | 保持远端 Agent/插件语义，但模型出口在本机 | 本机失联后下一次模型请求失去通路；已有计算是否继续取决于远端程序 |
| 远端 Agent、独立常在线模型出口 | 远端不能直接访问模型，且本机需要离线 | 常在线出口可达时仍可继续；出口部署、认证和费用另行确定 |

模式在新建工作区/会话时明确选择，显示模型请求从哪里发出，不静默更换现有会话的所有者。官方 provider 的租约语义和我们的独立 daemon 生命周期保持区分。[官方 SSH 生命周期](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/ssh.md)

本机中继如实现，限定到用户选择的模型服务，绑定回环、认证和主机信任检查齐全；不转发任意本机地址，不把本机主密钥复制给远端。支持哪些协议、流式响应和错误必须逐一验收。

可选离线附件采用用户选择或明确大小规则、内容哈希和引用计数；清除会话副本不能删掉其他会话仍引用的文件。正文搜索索引可重建，附件不是“存了事件引用就已经下载”。这些增强不推迟基础历史的可靠保存。

## 12. 测试与发版门槛

### 必须保持的契约

严格核验目标及每层跳板机 known_hosts；不自动重放已派发动作；无遥测；不自动迁移凭据或改变模型配置；不因本机退出而停止独立远端 DSH；历史默认永久保留；本机清理不影响远端任务。

### 验证层次

| 层次 | 最小覆盖 |
| --- | --- |
| 单元/契约 | 主机路由、能力表、游标/代次、迁移、清除屏障、单写入者和迟到响应 |
| 真实 SSH | 目标/跳板密钥、认证等待、断流、丢 ACK、同 shell/服务身份、实际副作用计数 |
| 隔离 DSH 安装 | 最终归档在 `0.2.0-rc.2`、`0.2.1-alpha.4`、`0.2.1-rc.2`；历史声明版本单列回归，不把旧结果算本轮重跑 |
| 原生桌面 | macOS 真实窗口，本地/两远端、模型入口、草稿、焦点、快捷键和离线历史；Windows 要单独实机通过才扩大支持声明 |
| 性能 | 固定基线、网络与数据；延迟、失败率、内存、磁盘写入和总流量一起报告 |
| 长时/故障 | 控制器和应用重启、睡眠、网络切换、磁盘满/损坏；稳定候选做 24 小时隔离持续运行，保留故障而不只取成功时段 |

每轮按改动补最小有意义的检查；部署前必须运行 `pnpm test`、`pnpm typecheck`、`pnpm build`、产物检查和隔离 runtime smoke。保持原有通过项；有新增功能还要验证本轮命名的边界，不能靠总测试数代替。

### 发布和安装

1. 在干净公共 checkout 准备发行，只提交本轮明确改动；私有开发包保持 private，既有未提交改动不混入。
2. 用同一个最终归档做兼容/SSH/性能验收，冻结校验值。新协议和新存储先通过能力开关逐步启用；官方不可用时保留旧接口路径。
3. 在已授权的发行范围内推送匹配版本标签，通过现有 GitHub Actions/npm OIDC 发布，不重建第二个包、不更改账户信任配置。
4. 核对 npm、实际镜像 CDN、GitHub Release 下载字节与测试归档一致，再按包名隔离安装。
5. 更新日常安装前保存草稿、正常退出本机 DSH，对选定配置/会话/历史及其他插件做受限备份和清单核对。远端任务继续运行，不为升级本机而重启远端。
6. 安装后核对版本/构建，再恢复原会话；检查原配置和模型、历史连续性、本地/远端切换、远端服务身份及任务事实。新产生的正常记录与意外修改分开比较。
7. 发现发布阻断问题保留失败证据。运行代码可切回上版；数据按对应格式导出/验证后回退，不以恢复整份旧备份覆盖新历史或复活用户已清除的副本。
