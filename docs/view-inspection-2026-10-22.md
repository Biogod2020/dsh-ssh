# 视图内存与未保存内容的采样基础

这是后续内存预算策略的基础，尚未启用自动释放视图，也尚未发行。

每个远端客户端新增只读 `inspection()`，输出当前导航、全部会话的侧栏标签/终端数量、草稿保存状态及卸载保存计数。公开的 `sidebarRight.openTabs` 包括未显示的会话，因此隐藏终端也能计入。采样不打开、关闭或执行终端，不发模型请求。

Chromium 提供 `performance.memory.usedJSHeapSize` 时可取得渲染器 JavaScript 堆估计；它不包含原生/GPU 内存，也不保证属于一个独占视图。缺失或无效数据返回 `null`。本轮没有把固定的八视图上限当成内存预算，也没有声称已经测得原生进程 RSS。

输出只保留固定的生命周期字段：不包含草稿文字、文件引用、附件句柄、侧栏资源地址或扩展字段。缺失的服务保持未知；`lifecycle.scope` 明确为 `observation-only`，请求与未确认操作状态仍为 `null`。调用方不能把这份采样当成释放视图的原子许可。

## 不让未结清保存被误认成成功

卸载的草稿实例在保存和失败后的只读确认结束前，继续计入待结清。保存失败时保留失败记录；新出现的空草稿或不同文字不能自动清掉旧失败。只有同一主机、同一会话的相同文字与引用/附件标记确认落盘，才消除该记录。

本轮还修正了两处边界：

- 启动时的草稿种子只在实际读取时消费一次，避免反复挂载使用旧空种子。后续挂载读取当前磁盘，已有浏览器空输入不会被旧文字覆盖。
- 旧请求迟到失败时，即使新实例已经成功保存并卸载，也能由一次有超时的只读 GET 核对落盘结果，不依赖仍有活动实例，也不重放写入。

关闭视图的中英文提示现在明确区分已保存文字、需要重新选择的引用/附件，以及可能随视图结束的终端；远端 Agent 任务仍由远端服务持有。
