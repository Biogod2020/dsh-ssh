# 本次核心版本的交付与验收

2026-10-23，用户调整执行要求：优先实现核心目标，以真实端到端使用验证作为交付依据。本文取代原路线图中固定 100/30 次原生采样、最终候选 24 小时持续运行及每次发布全套压力矩阵的强制要求。已有测量、失败记录和测试保留，不把未完成的专项算成通过。

## 本次交付

- 本地与远端项目、会话同窗展示和切换；缓存内容先显示，联网校验在后台进行。
- 远端历史长期写入本机磁盘，按窗口读取，只补缺少事件；用户选择清理并收到空间提醒。
- 会话各自保存文字草稿，应用重启后可恢复；保存失败时保留文字并提示处理。
- 远端消息/代码复制、重命名、置顶、归档/恢复及所属主机的模型设置入口可用。
- 断线重连保留本机可读副本，不重放已派发动作，不为本机升级重启远端服务。

本次继续保留已加载的远端视图。自动内存预算回收及其完整网关/Client 冻结机制作为后续迭代，不阻塞这批核心功能发布；当前部分操作观察不能宣称完整释放保护已经完成。正式上游接口和额外网络模式也不计入本次交付。

## 实际使用验收

按用户后续要求，全部交互验收使用内置浏览器的 Web 界面，不操作桌面 App。使用独立 Home、生成的 SSH 主机/消息和固定模型夹具，不操作用户正式会话。验证准确安装包的实际 JS，不仅核对依赖记录；不把 Web 通过写成新的原生桌面验收。

1. 安装并打开 DSH：本地与远端会话在同一窗口切换，草稿属于各自会话，远端模型设置进入正确主机。
2. 实际点击消息和代码复制按钮，再粘贴核对中文、多行和代码；实际完成重命名、置顶、归档及恢复，并重开历史。
3. 阅读磁盘历史，接收远端新事件后补齐；无变化校验不重传历史正文。只清除选定的本机副本，其他副本和远端历史保留。
4. 停止并重新启动本机测试控制器，确认历史/草稿仍可读、连接恢复、远端原服务身份保留。模拟一次断线，检查宿主仍可用且没有自动重发。

项目要求的 test、typecheck、build、产物检查和隔离安装继续运行。存储/网络大样本基准、内核丢包矩阵和长时观察保留为按需工具，手动选择 `all` 或 `kernel-only` 执行；本次不再新增纯计数、重复实现或与核心使用无关的检查。
